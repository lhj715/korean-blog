# «이유» 다시 쓰기 검토 지시 (독립 검토자)

너는 쓴 사람이 아니다. `D:\Work\블로그\리딩맵\작업\_이유\묶음_NN.json`(원래 맥락)과 `결과_NN.json`(새 이유)을 대조한다. 값이 null 이 아닌 항목을 **전부** 본다.
기준(`D:\Work\블로그\리딩맵\도구\템플릿\이유_작업지시.md` 와 같다):
1. 사실: 지문·<보기>·해설지 인용에 없는 말이 없는가. 따옴표 속 글자가 원문 그대로인가(passages 와 대조).
2. 판정과 맞는가: verdict 를 뒷받침하는 이유인가. 틀린 선지는 틀린 부분을 정확히 짚는가.
3. 이해: 학생이 읽고 «왜» 를 알 수 있는가. 선지를 되풀이만 하지 않는가. 문장이 자연스러운가.
4. 말투 «~다», em dash·메타 문구 없음.
null 로 둔 항목도 표본(10개 이상)을 보고 정말 그대로 둬도 되는지 본다.
결과를 `작업\_이유\검토_NN.md` (재검토면 `검토_NN_2차.md`) 에 쓴다: «반드시 고칠 것»(항목 id 와 까닭, 고칠 방향)과 «고치면 좋은 것». 문서 맨 끝 줄은 `최종 판정: 통과` 또는 `최종 판정: 수정 필요`.
파일은 검토 파일만 만든다. 결과·세트·도구는 고치지 않는다. 유료 AI API 는 쓰지 않고 언급하지 않는다. 최종 답은 판정과 «반드시 고칠 것» 수만 짧게.
