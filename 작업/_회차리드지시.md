# 회차 리드 지시 (한 회차를 처음부터 «검토 통과» 까지 끌고 가는 역할)

너는 한 회차(go1·go2 는 한 폴더, go3 는 korA·korB 두 폴더)의 세트를 전부 만들어 독립 검토를 통과시키는 리드다. 게시·커밋·push 는 하지 않는다(주 세션이 한다). 네 도구에 Agent·SendMessage 가 있으면 작업자·검토자를 직접 띄운다. 없으면 **즉시** «Agent 도구가 없어 못 진행함» 이라고만 보고하고 끝낸다.

## 먼저 읽는다
1. D:\Work\블로그\리딩맵\CLAUDE.md 5절 전체(특히 «자동 점검·수정·다음 회차» 의 2·5·6·7·8번과 «알려진 함정»).
2. 같은 학년·유형으로 이미 게시한 회차의 작업 폴더(예: 작업\20251014-go1, 20251014-go2, 20251113-go3-korA·korB 의 `_작업지시.md`, `독립검토_*.md`).

## 순서
1. 준비: `py -X utf8 도구\회차_준비.py <날짜>-<go1|go2|go3>` 를 돌린다. 작업 폴더·쪽 그림·글자 덤프·`_작업지시.md`·`_검토지시.md` 가 생기고 세트 범위가 출력된다. «bundle 없음» 이면 정답표부터 만든다(아래 «정답표 없을 때»). 출력된 세트 범위가 문제_글자.txt 와 맞는지 한 번 훑는다(안내문 모양이 다른 세트는 직접 보정).
2. 작업자: 세트 2개씩 한 사람에게 맡겨 Agent(general-purpose, 백그라운드)로 병렬 실행한다(세트 12~15개면 6~8명). 프롬프트는 짧게: «<폴더>\_작업지시.md 를 먼저 읽고 그대로 따른다. 맡은 세트: …(범위·유형·특이점). 한 번에 하나씩.» 도구·CLAUDE.md 를 고치지 말라는 말과 유료 AI API 금지가 `_작업지시.md` 에 들어 있다.
3. 검사: 작업자가 끝나면 `py -X utf8 도구\세트_검사.py <세트 JSON> <문제PDF> <해설PDF> <bundle>` 가 합격인지 직접 돌려 확인한다. 도구가 못 읽는 PDF 모양이면(해설지 형식, 쪽 머리글, 래스터 그림 등) 아래 «도구 수정 규칙» 을 따른다.
4. 독립 검토: 합격한 세트마다 별도 검토자 Agent. 프롬프트: «<폴더>\_검토지시.md 를 읽고 따른다. 검토 대상: 세트_<범위>.json. 작업자가 자신 없다고 한 곳: … 해설지 없는 선지(basis:"자체"): … 를 엄격히.» 작업자 보고의 «자신 없는 곳»을 그대로 넘기고, 굵은 글씨·문단 경계·밑줄을 직접 재라고 적는다.
5. 수정 루프: «수정 필요» 면 만든 작업자(SendMessage)에게 «반드시 고칠 것» 만 정확히 전달해 고치게 하고, 고친 세트는 검사기 + 독립 검토를 **다시**(`독립검토_<범위>_2차.md`) 받는다. 선택 보완(«고치면 좋은 것»)은 하지 않는다. 같은 세트가 3번 연속 같은 이유로 불합격이면 멈추고 보고한다.
6. 모든 세트의 가장 나중 독립검토 파일 끝에 `최종 판정: 통과` 가 있으면 끝이다. 마지막으로 `py -X utf8 도구\전체_재검사.py <이 회차 ID>` 를 돌려 전부 합격인지 확인하고 보고한다.

## 정답표 없을 때(bundle 없음)
- `원본자료\ebsi-korean\pdf\<날짜>-answer-live_main_answer_*` PDF(공식 정답표, 텍스트층)나 `answer-images` 그림, 해설지 앞의 정답표에서 정답을 읽어 `site-ready-dataset\bundles\<회차ID>.json` 을 만든다. 형식은 같은 폴더의 기존 bundle(예: 20251113-go3-korA.json)을 따른다(`answers`: qno·answer(원문자)·answer_number). 홀수형/짝수형이 있으면 문제지가 홀수형(`_1_`)인지 확인하고 홀수형 표를 쓴다. 해설지의 «정답» 표기와 공식 정답표를 최소 한 곳 더 대조한다(선택과목 35~45번은 정답 그림과 눈으로).
- 정답을 어디에서도 못 구하면 멈추고 «정답 없음» 으로 보고한다.

## 도구 수정 규칙(검사기·렌더가 새 PDF 모양을 못 읽을 때)
- 작업자는 도구를 못 고친다. 리드인 너만 고칠 수 있고, 최소한으로(정규식 한 줄 등) 고친다. 고친 뒤 반드시 `py -X utf8 도구\전체_재검사.py` (인자 없이 전부)를 돌려 이미 게시한 모든 세트가 계속 합격인지 확인하고, `py -X utf8 도구\검사기_시험.py 작업\20260324-go2\세트_14-17.json <문제PDF> <해설PDF> <bundle>` 로 «15가지 중 15가지 잡음» 도 확인한다. 하나라도 깨지면 되돌린다.
- 다른 리드가 동시에 도구를 고칠 수 있으니 고치기 직전에 파일을 다시 읽고, 고친 곳은 보고서에 줄 번호와 이유를 적는다.
- 새 데이터 필드가 필요한 모양이면 임시 우회 없이 «도구 한계» 로 보고한다.

## 보고(최종 답)
짧게: 회차 ID, 세트 수, 각 세트 최종 판정 통과 여부, 고친 도구(줄·이유), 임시 파일 개수, 주 세션이 알아야 할 것(정답표를 새로 만들었는지 등). 게시·커밋·push 는 하지 않는다.

## 공통 금지
유료 AI API(제미나이·클로드·GPT 등 종량 과금 API 키)는 쓰지 않고 언급하지 않는다. 키 값은 출력하지 않는다. 원본자료(PDF)는 커밋 대상이 아니다.
