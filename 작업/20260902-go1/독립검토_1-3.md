검토 방법: 쪽 그림(문제_1쪽.png)과 해설지로 먼저 풀고(1번 ①, 2번 ②, 3번 ③ = 정답표와 같음), PyMuPDF 로 굵은 글씨(texttrace type·font), 문단 시작 x 좌표, 밑줄 선 좌표를 직접 재고, 미리보기를 화면에 띄워 확인. `세트_검사.py` 는 합격(해설지 없는 선지 1번 ④·⑤ 확인 요청만 나옴).

## 반드시 고칠 것

1. **2번 계획표 상자 맨 위에 쓰레기 줄이 독자에게 보인다.** 미리보기에서 상자 첫 줄에 `………①………③………②………④………⑤` 가 그대로 찍힌다(②와 ③ 순서도 뒤바뀜). 원본에는 이런 줄이 없고, 점선과 번호는 각 ◦ 항목 오른쪽에 하나씩 붙어 있다(문제_1쪽 그림: ①~⑤ 가 항목 옆). 검사기 C8 을 통과시키려고 넣은 note 라서 데이터를 고쳐서는 해결되지 않는다. 주 세션이 도구에서 해결해야 한다. 권장: `choices_in_box` 문항의 이 note(id `n1`)는 화면에 그리지 않거나, 번호를 항목 끝에 붙여 그린다. 도구를 고친 뒤 이 세트를 다시 렌더해 확인하고 2차 검토를 받는다. 그때까지 게시 불가.

(판정·인용·밑줄·굵은 글씨·문단 경계에는 반드시 고칠 오류가 없었다. 위 1건은 화면 표시 문제다.)

- **3번 대화 상자(작업자 우려)**: 말풍선 좌우 정렬은 도구가 못 그린다. 원본은 지원 말풍선이 왼쪽, 정수 말풍선(ⓑ·ⓒ·ⓔ)이 오른쪽이고, 세트·화면은 모두 왼쪽 한 줄이다. «지원» 글자는 PDF 에 있는 왼쪽 이름표라 데이터에 두는 것이 맞다(ⓐ·ⓓ 줄 앞). 학습에는 지장 없는 화면 한계로 본다.
- **basis:"자체" 선지(엄격 확인)**: 1번 ④ «구체적인 수치»: 지문에 수치가 없음(‘2026년 8월’ 같은 날짜는 지문이 아님). 이유 «줄임말 뜻풀이와 띄어쓰기 사례» 는 사실. 1번 ⑤ «정보의 출처»: 지문에 출처를 밝히는 말 없음, «지난 시간에 배웠던…» 은 출처 표기가 아니라 질문. 둘 다 판정·이유 맞음.
- **이유 문장**: em dash 없음, «해설지는…» 메타 문구 없음. 지문·해설지 밖 내용 없음.
