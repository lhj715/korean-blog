# 독립 검토 3차: 2026-03 고2 34~38번 (굵은 글씨 반영 확인)

검토 범위: 오늘 추가된 지문 굵은 글씨(`bold`) 16구절이 원본과 같은지, 빠진 굵은 글씨가 없는지, 판단·근거가 바뀌지 않았는지.

## 확인 방법

- 원본 PDF(`20260324-go2-problem-kor_mun_Q97689G9.pdf`) 12쪽 오른쪽·13쪽 왼쪽·14쪽 왼쪽을 PyMuPDF 로 200dpi 렌더해 눈으로 확인.
- `page.get_texttrace()` 에서 획 처리(type 1)된 글자를 줄 단위로 모아 굵은 구간 목록을 뽑고, 쪽 그림과 대조.
- 세 쪽의 글꼴 목록도 확인: 지문·상자 글자는 모두 'Haansoft Batang' 한 글꼴이라 굵은 글꼴로 따로 찍힌 글자는 없음(그 밖의 글꼴은 쪽 머리글·문항 안내·31~33번 도식뿐).
- `도구/미리보기.py` 로 미리보기를 다시 만들어 `xm-b` 표시 구간을 확인.
- `git diff` 로 세트 JSON 변경 내용 확인.

- 빠진 것: 없음. texttrace 굵은 구간에서 위 16개 외에 나온 것은 (가)·(나)·(다) 소제목, 문항 번호(34.~38.), 안내문 "[34 ~ 38] …", 쪽 머리글뿐이다. 소제목·안내문은 화면에서 이미 따로 모양을 갖는 요소라 `bold` 대상이 아니다.
- 더 들어간 것·범위 틀린 것: 없음.
- (가) 앞부분(㉠~'사람의 눈이 …'), (다) 앞부분(부구공의 첫 말 ~ ⓑ 선문자 문단), (중략) 뒤 첫 줄 '이에 선문자가 …' 는 그림으로도 보통 글씨임을 확인.
- 문항 상자: 35번·38번 <보기>(13쪽 오른쪽·14쪽 왼쪽)와 34~38번 선지에는 지문 쪽에서 쓰인 굵은 글씨가 없다(texttrace 14쪽 왼쪽 결과는 37·38 번호뿐). 14쪽 오른쪽의 굵은 구간('고개를 돌', '수모를 삼키고 …' 등)은 39~42번 지문이라 이 세트 밖이다.

## 화면(미리보기) 확인

- `xm-b` 구간 16개가 위 표와 같은 순서·글자로 찍힌다. '강가에 버' + 보통 '렸도다', d6 첫 '나를 군자라고 하는'만 굵고 같은 문단 셋째 줄의 '나를 군자라고 하는'은 보통으로 나온다.
- 굵은 구간이 근거 밑줄(`xm-ev`) 구간과 겹치는 곳(귀도 또한 별일이지, 나를 군자라고 하는, 근본은 나에게 있, 힘쓸 바를 …)도 근거 표시 data-ev 가 끊기지 않고 앞뒤 조각에 똑같이 붙어 있다.

## 판단·근거 변경 여부

- `git diff` 결과 `세트_34-38.json` 의 변경은 v1·v2·d6·d7 의 `"bold"` 추가뿐이다. `questions`·`judgments`·`evidence`·`underlines`·`text` 는 한 글자도 바뀌지 않았다.
- `세트_34-38_만들기.py` 변경도 굵은 글씨 등록과 "글자가 문단에 있는지" 확인문(assert)뿐이다.
- `도구/세트_검사.py` 재실행: 합격.

## 참고 (도구 쪽 주의)

- 1~3번 <보기>의 A·B 처럼 texttrace 로는 획 처리(type 1)가 잡히지만 그림에서는 보통 굵기인 글자가 있다. 굵은 글씨를 texttrace 만으로 정하면 오탐이 생기므로 지금처럼 쪽 그림 확인을 같이 해야 한다. 이 세트의 16구절은 그림에서도 모두 굵다.

최종 판정: 통과
이유: 원본 (가)(나)(다)의 굵은 글씨 16구절이 세트 파일과 글자·범위(낱말 중간에서 끊기는 '강가에 버', '근본은 나에게 있' 포함)·몇 번째 나오는지까지 모두 맞고, 빠진 것도 더 들어간 것도 없다. 판단·근거·밑줄·본문은 바뀌지 않았고 프로그램 검사도 합격이다.
