# 독립 검토 (2차): 20250710-go3-korA 세트 1~3번

## 1차 «반드시 고칠 것» 확인
1. 3번 <보기> 밑줄: ⓐ·ⓑ 는 `no_line` 제거 후 C3 통과(검사기 허용치 -1.2). ⓒ·ⓓ·ⓔ 는 `no_line:true` 로 남았다.
   - 직접 잰 결과: PDF 에 선이 실제로 있고(쪽 1, 6줄째 344.8~524.8 / 7줄째 327.3~373.2 와 417.6~524.8 / 8줄째 327.3~429.5 / 9줄째 361.4~498.0), 선 위 글자를 읽으면 ⓒ «여러책을찾아…중심으로 / 비교하며읽었다», ⓓ «‘문화권마다…다를수 / 있다.’…새로알게되었다», ⓔ «연구보고서의…떠올랐다» 로 데이터 글과 정확히 같다. 쪽 그림 확대에서도 같은 범위에 밑줄이 있다.
   - 선이 글자 아랫변보다 위에 뜬 정도는 줄마다 조금씩 커진다(2줄째 -1.15 → 9줄째 -1.29pt). 그래서 -1.2 허용치에서는 6줄째(-1.23) 이후가 읽히지 않는다. 즉 «선이 없다» 가 아니라 «검사기가 못 읽는다» 이고, 이 `no_line` 은 도구 한계 우회로서 사실과 어긋나지 않는다(선 위치는 검토자가 확인).
   - 화면 도구는 `no_line` 을 쓰지 않으므로(도구 폴더 검색으로 확인) 표시에는 영향이 없다.
   - 판정: 이번 세트에서는 수용한다. 다만 이후 같은 PDF 형식 회차가 계속 나오므로, 주 세션이 도구에 «세트별 허용치»(예: `meta.underline_tol`, 기본 1.2) 를 두어 이 세트만 1.4 로 올리고 `no_line` 을 걷는 것을 권한다(다른 회차에는 영향 없음). 또는 허용치를 «줄마다 가장 가까운 선» 방식으로 바꾸는 방법이 있다. 둘 다 이번 게시의 조건은 아니다.
2. 2번 ④ 근거: 4문단 «즉시 답을 구하는 대신 … 답을 찾게 될 수 있다는 것이다.» 로 교체됨. 이유(보류의 이유는 탐구 지속, 중요도 구별은 없음)와 맞는다. 해결.
